# Cruz Schedule

App interno (PWA) da Cruz Solutions Services Corporation para montar a escala diária das equipes ("schedule") e gerar a mensagem do WhatsApp. O usuário (Bruno) fala português; responda em português, em linguagem simples (ele não é programador).

## Como funciona
- Site estático no GitHub Pages: https://cruzsolutionsapp.github.io/cruz-schedule/ (branch `main`, pasta raiz). Cada push em `main` publica sozinho.
- Login e banco de dados: Firebase (projeto `cruz-schedule`), Auth e-mail/senha + Firestore (edição Standard).
- `index.html` — telas (login, portão de acesso, app). `style.css` — estilos (tokens de cor no topo, tema claro/escuro).
- `app-core.js` — toda a lógica do schedule (script clássico; expõe `window.startApp(db, ctx)`). Usa um adaptador `db.doc(path).set/get/onSnapshot` e `db.collection(path).where/orderBy/limit/get`.
- `auth.js` — módulo ES: Firebase, login, verificação de e-mail, lista de acesso (`members`), adaptador do banco, registro do service worker.
- `sw.js` — offline. **Ao mudar arquivos do app, aumente `VERSION` em `sw.js`.** Arquivos do app: rede primeiro com `?_=hora` (fura o cache de até 10 min do CDN do GitHub Pages); offline usa o cache.
- `index.html` tem Content-Security-Policy (meta): scripts só de self/gstatic/cdnjs; conexões só googleapis/firebaseio/firebaseapp. Se adicionar serviço externo novo, liberar lá (senão o navegador bloqueia).
- `firestore.rules` — regras de segurança (endurecidas 19/10: members só o próprio ou admin lê; `dayOk` valida campos/data/≤150 obras em days; dayhist e tvping só campos certos; `rosterOk` ≤1000 nomes). Não são publicadas automaticamente: o usuário cola no Console do Firebase → Firestore → Regras.

No dia só aparece uma bolinha de cor (verde/laranja ≥85%/vermelho acima); os números aparecem no topo (#calInfo) ao passar o mouse, e no painel do dia ao tocar.

Página do próximo dia (faixa laranja "AMANHÃ →", obras com shop/start, cidade, pessoas e "sem equipe ainda"/"falta X") entra no rodízio a partir do meio-dia, ou antes se todas as obras de hoje já saíram; depois das 15h a Central mostra SÓ o próximo dia (pílulas viram obras amanhã · pessoas escaladas/precisas · vagas abertas); se o fim de semana estiver vazio, mostra o próximo dia com obra (até 4 dias, lê `days` ao vivo). Relógio/batida a cada 1s: se a página ficou parada >1 min (TV dormiu) ou em visibilitychange/focus/pageshow/online, re-renderiza e confere versão na hora. Na virada do dia a Central recarrega a página sozinha (o login continua) e, a cada 5 min, confere o `VERSION` do sw.js: se mudou e ninguém está mexendo (sem PIN/janela aberta), recarrega pra pegar a versão nova. ## Formato da mensagem do WhatsApp (não mudar sem pedir)
Obras da mesma companhia saem juntas na mensagem (`msgOrder`, opção A escolhida pelo Bruno: só junta, sem numerar; a ordem na escala não muda).
```
Sexta-feira
10/09        (dia da semana + mês/dia, uma vez no topo)

✅ Companhia
Endereço   (ou "(Esperando)")
🔴 Calca👖|Bota 🥾
🔴 6:30am no shopp
⏰ start 7:30am
(Observação)
(All Week)

	✓ Motorista 🛻(51)
	✓ Nome
__
```
